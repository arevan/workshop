title: Git в двух фразах

Git запоминает состояния проекта, чтобы можно было вернуться назад. Учить его не нужно: всю работу делает агент, тебе хватит двух фраз.

Обязательная часть здесь одна — коммиты. Всё остальное в этом разделе понадобится, только если захочешь хранить копию проекта на сайте; для хакатона это не требуется.

## Две фразы

**«Сделай коммит»** — сохранить текущее состояние. Говори каждый раз, когда что-то заработало.

**«Откатись к прошлому коммиту»** — вернуть проект к сохранённому состоянию. Говори, когда после правки стало хуже.

Коммит — твоя рабочая точка. Без неё каждая правка агента риск: сломает работающий экран, и вернуть будет нечего. С коммитами цикл спокойный: заработало → коммит → пробуем дальше → не вышло → откат.

На хакатоне сделай коммит сразу, как основной сценарий начал проходиться целиком. Даже если дальше всё пойдёт не так, останется то, что можно сдать.

> Коммиты и откаты работают **на твоём компьютере**: без аккаунтов, регистрации и интернета. Начать можно прямо сейчас, ничего не устанавливая.

## Единственная настройка

Git подписывает каждый коммит именем и почтой. Пока их нет, первый же коммит закончится ошибкой вида `Please tell me who you are` — это не поломка, просто git не знает, кто ты.

Набирать ничего не нужно, попроси агента:

```
Настрой git: имя «Имя Фамилия», почта «почта@example.com».
```

Если он ответит, что git не установлен, скажи «поставь git» — на Mac система предложит доустановить его сама. Дальше можно работать: коммить, откатываться, снова коммить.

## Что где лежит

Дальше пойдёт речь о сайте, и тут легко запутаться, поэтому коротко про устройство.

**На компьютере** — сам проект и вся история коммитов. Она хранится в скрытой папке внутри проекта, поэтому история едет вместе с папкой, даже если скопировать её на флешку.

**На сайте** — копия того же самого. Она не появляется сама: копия обновляется, только когда ты её отправляешь. Это отдельное действие, называется **push**.

То есть коммит и отправка на сайт — разные вещи. Коммит сохраняет состояние у тебя. Push отправляет накопленные коммиты в интернет. Можно коммитить месяцами и ни разу ничего не отправлять.

## Зачем вообще сайт

Резервная копия, если с компьютером что-то случится. Доступ к проекту с другого компьютера. И ссылка, которой можно поделиться вместо архива.

Нужен аккаунт: открой [github.com](https://github.com), нажми **Sign up** и заведи по почте. Минута, подтверждение письмом.

## Как отправить проект на сайт

Самый короткий путь — приложение [GitHub Desktop](https://desktop.github.com). Оно делает мышкой то, что иначе пришлось бы набирать командами, и само разбирается с доступами: никаких токенов копировать не нужно.

1. Установи и открой приложение
2. Нажми **Sign in to GitHub.com** — откроется браузер, подтверди вход и вернись в приложение
3. **File** → **Add Local Repository** → выбери папку своего проекта
4. Нажми **Publish repository** в верхней части окна
5. В открывшемся окне оставь галочку **Keep this code private** — репозиторий будет закрытым, видным только тебе
6. Ещё раз **Publish repository**

Готово, проект на сайте.

Когда захочешь обновить копию, открывай приложение и жми **Push origin** — «origin» это и есть твой репозиторий на сайте, кнопка отправляет туда все коммиты, которых там ещё нет.

## Приложение и агент — один и тот же проект

Это не два разных места и не два разных репозитория. Агент и приложение работают с одной папкой, просто по-разному: агент — словами, приложение — кнопками.

Поэтому коммиты, которые сделал агент, видны в приложении: открой вкладку **History** — там вся история с датами и списком изменённых файлов. Удобно, чтобы наконец увидеть глазами, что такое коммит.

Разделение простое: коммиты продолжай делать через агента, приложение открывай, чтобы отправить их на сайт.

## Если что-то пошло не так

**«This directory does not appear to be a Git repository»** при добавлении папки — значит, в проекте ещё нет истории. Нажми предложенную ссылку **create a repository**, или скажи агенту «сделай коммит», и папка станет репозиторием.

**Кнопки Publish repository нет** — скорее всего, выбрана не та папка. Нужна папка самого проекта, та, которую ты открываешь в агенте.

**Просит войти снова и снова** — выйди из аккаунта в приложении и войди заново через браузер.

**Агент говорит, что не может запушить** — если публикацию делает приложение, агенту это и не нужно: просто нажми **Push origin** сам.

## Через терминал, если так привычнее

Создай пустой репозиторий на [github.com/new](https://github.com/new): имя латиницей, **Private**, ничего не отмечать в «Initialize this repository». Скопируй адрес и скажи агенту:

```
Привяжи проект к репозиторию https://github.com/имя/название.git и запушь всё, что есть.
```

При первом пуше попросят войти. Проще всего поставить [GitHub CLI](https://cli.github.com) и выполнить `gh auth login`, выбрав **GitHub.com** → **HTTPS** → **Login with a web browser**. Дальше достаточно фразы «запушь изменения».

## Если просят токен

Во внутреннем репозитории компании вход через браузер может не работать — там понадобится токен доступа. Тогда важно не выдать лишнего.

На GitHub бери **fine-grained**, а не classic:

1. Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
2. **Repository access** → **Only select repositories** → выбери один свой репозиторий
3. **Permissions** → **Contents** → **Read and write**
4. Срок жизни — короткий, 30 или 90 дней

> Classic-токен со scope `repo` открывает доступ **ко всем** твоим репозиториям и репозиториям организаций — один ключ сразу ко всему. Fine-grained ограничен одним репозиторием и правом менять только файлы: если он утечёт, потери ограничены учебным проектом.

Токен — это пароль. Не вставляй его в чат с агентом, не клади в файлы проекта и не пересылай в мессенджере.

## Где может жить код

Локально — всегда можно. Во внутреннем репозитории компании — можно.

> Публичный GitHub для кода банка закрыт. Код, попавший в публичный репозиторий, считается утёкшим, даже если удалить его через минуту: он успевает разойтись по зеркалам и поисковым индексам. Это касается и демок со скриншотами боевых экранов, внутренними ссылками или доступами внутри.

Учебные демки без реальных данных — можно на GitHub. Сомневаешься — оставь локально.

## Что делать не нужно

Разбираться в ветках, merge и pull request. Для демок хватает линейной истории коммитов. Понадобится работать в команде над одним проектом — тогда и разберёшься, а агент объяснит на твоём же коде.
