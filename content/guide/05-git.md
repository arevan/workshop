title: Git в двух фразах
slug: git
---

Git запоминает состояния проекта, чтобы можно было вернуться назад. Учить его не нужно: всю работу делает агент, тебе хватит двух фраз.

Обязательная часть здесь одна — коммиты. Копия проекта на сайте нужна не всем и для хакатона не требуется.

## Две фразы

**«Сделай коммит»** — сохранить текущее состояние. Говори каждый раз, когда что-то заработало.

**«Откатись к прошлому коммиту»** — вернуть проект к сохранённому состоянию. Говори, когда после правки стало хуже.

Коммит — твоя рабочая точка. Без неё каждая правка агента риск: сломает работающий экран, и вернуть будет нечего. С коммитами цикл спокойный: заработало → коммит → пробуем дальше → не вышло → откат.

На хакатоне сделай коммит сразу, как основной сценарий начал проходиться целиком. Даже если дальше всё пойдёт не так, останется то, что можно сдать.

> Коммиты и откаты работают **на твоём компьютере**: без аккаунтов, регистрации и интернета. Начать можно прямо сейчас, ничего не устанавливая.

## Единственная настройка

Git подписывает каждый коммит именем и почтой. Пока их нет, первый же коммит закончится ошибкой `Please tell me who you are` — это не поломка, просто git не знает, кто ты.

Набирать ничего не нужно, попроси агента:

```
Настрой git: имя «Имя Фамилия», почта «почта@example.com».
```

Если он ответит, что git не установлен, скажи «поставь git» — на Mac система предложит доустановить его сама. Дальше можно работать: коммить, откатываться, снова коммить.

## Копия на GitHub

Дальше у проекта будет две копии: локальная на твоём компьютере и на GitHub. Локальная работает всегда, копия на GitHub обновляется, когда скажешь агенту «запушь изменения».

Нужна она ради трёх вещей: резервная копия, доступ к проекту с другого компьютера и ссылка, которой можно поделиться вместо архива. Если ничего из этого не нужно — пропускай остаток раздела.

Настроить можно двумя способами: через сайт или через терминал. Достаточно одного.

## Путь первый: через сайт

Ничего устанавливать не надо, всё делается в браузере и одной фразой агенту.

**1. Заведи аккаунт.** Открой [github.com](https://github.com), нажми **Sign up**, зарегистрируйся по почте. Запомни свой ник — он понадобится.

**2. Создай репозиторий.** Открой [github.com/new](https://github.com/new):

- **Repository name** — название латиницей, без пробелов
- **Visibility** — **Private**. Публичным сделать потом легко, обратно сложнее
- В блоке **Initialize this repository** ничего не отмечай — файлы уже есть в проекте
- **Create repository**

На следующем экране скопируй адрес вида `https://github.com/ник/название.git`.

**3. Создай ключ доступа.** Чтобы отправить проект, git попросит подтвердить, что репозиторий твой. Пароль от аккаунта для этого не подходит — нужен токен. Создаётся там же, на сайте:

- Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → **Generate new token**
- **Repository access** → **Only select repositories** → выбери свой репозиторий
- **Permissions** → **Contents** → **Read and write**
- Срок жизни — 30 или 90 дней

Токен показывается **один раз** — скопируй его сразу.

> Выбирай именно fine-grained. Classic-токен со scope `repo` открывает доступ ко **всем** твоим репозиториям сразу, одним ключом. Fine-grained ограничен одним репозиторием и правом менять только файлы: если он утечёт, потери ограничены учебным проектом.

**4. Отправь проект.** Скажи агенту:

```
Привяжи проект к репозиторию https://github.com/ник/название.git и запушь всё, что есть.
```

В терминале появится запрос логина: в поле **Username** введи свой ник, в поле **Password** вставь токен. Ввод пароля не отображается — это нормально, вставляй и жми Enter.

Дальше git запомнит доступ, и хватит фразы **«запушь изменения»**.

> Токен вводится только в этот запрос. Не отправляй его агенту в переписке, не клади в файлы проекта и не пересылай в мессенджере.

## Путь второй: через терминал

Если терминал не пугает, можно обойтись без токена: вход происходит через браузер, а ключ создаётся и хранится сам.

Установи [GitHub CLI](https://cli.github.com) и выполни:

```
gh auth login
```

Выбирай по порядку: **GitHub.com** → **HTTPS** → **Login with a web browser**. Подтверди вход в открывшемся окне.

Репозиторий тоже можно не создавать руками — попроси агента:

```
Создай приватный репозиторий на GitHub для этого проекта и запушь всё, что есть.
```

Дальше так же: **«запушь изменения»**.

## Немного безопасности

Локально — всегда можно. Во внутреннем репозитории компании — можно.

> Публичный GitHub для кода банка закрыт. Код, попавший в публичный репозиторий, считается утёкшим, даже если удалить его через минуту: он успевает разойтись по зеркалам и поисковым индексам. Это касается и демок со скриншотами боевых экранов, внутренними ссылками или доступами внутри.

Учебные демки без реальных данных — можно на GitHub. Сомневаешься — оставь локально.

## Что делать не нужно

Разбираться в ветках, merge и pull request. Для демок хватает линейной истории коммитов. Понадобится работать в команде над одним проектом — тогда и разберёшься, а агент объяснит на твоём же коде.
