Git запоминает состояния проекта, чтобы можно было вернуться назад. Учить его не нужно: всю работу делает агент, тебе хватит двух фраз.

## Две фразы

**«Сделай коммит»** — сохранить текущее состояние. Говори каждый раз, когда что-то заработало.

**«Откатись к прошлому коммиту»** — вернуть проект к сохранённому состоянию. Говори, когда после правки стало хуже.

Коммит — твоя рабочая точка. Без неё каждая правка агента риск: сломает работающий экран, и вернуть будет нечего. С коммитами цикл спокойный: заработало → коммит → пробуем дальше → не вышло → откат.

На хакатоне сделай коммит сразу, как основной сценарий начал проходиться целиком. Даже если дальше всё пойдёт не так, останется то, что можно сдать.

## Настроить один раз

Git на Mac обычно уже стоит вместе с Xcode. Проверь в терминале:

```
git --version
```

Если версии нет, macOS сама предложит доустановить — согласись. На Windows скачай с [git-scm.com](https://git-scm.com).

Дальше представься — git подписывает этим каждый коммит:

```
git config --global user.name "Имя Фамилия"
git config --global user.email "почта@example.com"
```

Всё. Больше команд набирать не придётся.

## Репозиторий на сайте

Пока проект лежит только на твоём компьютере, git — это история правок и кнопка «отменить». Репозиторий на сайте добавляет резервную копию, доступ с другого компьютера и возможность показать проект ссылкой.

Создаётся он в браузере, за минуту:

1. Открой [github.com/new](https://github.com/new)
2. **Repository name** — название латиницей, без пробелов
3. **Visibility** — выбери **Private**. Публичный можно сделать позже, наоборот сложнее
4. Ничего не отмечай в **Initialize this repository** — файлы уже есть в проекте
5. **Create repository**

На следующем экране будет адрес вида `https://github.com/имя/название.git` — скопируй его.

Дальше вернись к агенту и скажи своими словами:

```
Привяжи проект к репозиторию https://github.com/имя/название.git и запушь всё, что есть.
```

Потом достаточно фразы **«запушь изменения»**, когда хочешь обновить копию на сайте.

## Как войти, не раздав лишнего

При первом пуше git попросит авторизоваться. Способ, который проще и безопаснее остальных, — вход через браузер. Установи [GitHub CLI](https://cli.github.com) и выполни:

```
gh auth login
```

Выбирай по порядку: **GitHub.com** → **HTTPS** → **Login with a web browser**. Откроется браузер, подтвердишь вход — и git запомнит доступ сам. Ничего копировать и хранить не нужно.

Если вход через браузер невозможен и нужен токен — бери **fine-grained**, а не classic:

1. Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
2. **Repository access** → **Only select repositories** → выбери один свой репозиторий
3. **Permissions** → **Contents** → **Read and write**
4. Срок жизни — короткий, 30 или 90 дней

Токен вставляется вместо пароля при первом пуше, дальше git помнит его сам.

> Почему именно так. Classic-токен со scope `repo` открывает доступ **ко всем** твоим репозиториям и репозиториям организаций — одним ключом сразу ко всему. Fine-grained ограничен одним репозиторием и правом менять только файлы. Если такой токен утечёт, потери ограничены одним учебным проектом.

Токен — это пароль. Не вставляй его в чат с агентом, не клади в файлы проекта и не отправляй в мессенджер.

## Совсем без терминала

Если терминал не даётся, а сдать проект нужно: открой свой репозиторий на сайте, нажми **Add file** → **Upload files** и перетащи папку проекта прямо в браузер. Работает для файлов до 25 МБ и до 100 штук за раз.

Это не заменяет коммиты во время работы, но как способ выложить готовое — вполне.

## Что видно на сайте

**История коммитов** — все сохранённые состояния с датами; можно открыть любое и посмотреть, что менялось. Удобно, когда ищешь, после какой правки сломалось.

**Файлы проекта** — код читается прямо в браузере.

**Ссылка на проект** — то, чем делятся с коллегой вместо архива.

## Где может жить код

Локально — всегда можно. Во внутреннем репозитории компании — можно.

> Публичный GitHub для кода банка закрыт. Код, попавший в публичный репозиторий, считается утёкшим, даже если удалить его через минуту: он успевает разойтись по зеркалам и поисковым индексам. Это касается и демок со скриншотами боевых экранов, внутренними ссылками или доступами внутри.

Учебные демки без реальных данных — можно на GitHub. Сомневаешься — оставь локально.

## Что делать не нужно

Разбираться в ветках, merge и pull request. Для демок хватает линейной истории коммитов. Понадобится работать в команде над одним проектом — тогда и разберёшься, а агент объяснит на твоём же коде.
