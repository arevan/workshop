---
title: Git в двух фразах
slug: git
---

Git учить не нужно. Это система, которая запоминает состояния проекта, чтобы можно было вернуться назад. Всю работу с ней делает агент — тебе хватит двух фраз.

## Две фразы

**«Сделай коммит»** — сохранить текущее рабочее состояние. Говори это каждый раз, когда что-то заработало и тебе это нравится. Перед любой крупной правкой — тоже.

**«Откатись к прошлому коммиту»** — вернуть проект к последнему сохранённому состоянию. Говори, когда после правки стало хуже, и агент не может это починить за пару попыток.

## Зачем это на самом деле нужно

Коммит — это твоя рабочая точка. Пока её нет, каждая правка агента — риск: если он сломает работающий экран, вернуть будет нечего, кроме «попробуй починить», а это может увести ещё дальше.

С коммитами цикл становится спокойным: заработало → коммит → пробуем следующее → не получилось → откат к рабочей версии. Ничего не теряется, экспериментировать не страшно.

На хакатоне это особенно важно: сделай коммит сразу, как только основной сценарий начал проходиться от начала до конца. Даже если дальше всё пойдёт не так, у тебя останется то, что можно сдать.

## Что делать не нужно

Не разбираться в ветках, merge и pull request. Для демок это лишнее — линейной истории коммитов достаточно. Если позже захочешь работать в команде над одним проектом — тогда и разберёшься, а агент к тому моменту объяснит.

## Где может жить код

Локально на твоём компьютере — всегда можно.

Во внутреннем репозитории компании — можно.

> Публичный GitHub для кода банка закрыт. Это не формальность: код, однажды попавший в публичный репозиторий, считается утёкшим, даже если его удалить через минуту.

Это касается и демок, если в них попали внутренние доступы, реальные данные или скриншоты боевых экранов. Сомневаешься — оставь локально.
