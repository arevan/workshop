По умолчанию агент не знает, как выглядит твой макет. Ты описываешь экран словами, он собирает по описанию — и получается похоже, но не то: не те отступы, не тот оттенок, не тот компонент.

Это чинится подключением Figma к агенту напрямую. Тогда он открывает макет сам: видит цвета, размеры, переменные и компоненты — и собирает по ним, а не по пересказу.

## Что такое MCP

Технология называется **MCP** — это стандартный способ подключать к агенту внешние инструменты. Figma, трекер задач, база данных: подключается один раз, дальше агент обращается к инструменту сам, когда задача этого требует.

Знать про него больше не нужно. Достаточно понимать: MCP — это разъём, а Figma — то, что мы в него включаем.

## Что можно просить после подключения

- «Собери этот экран по макету» — со ссылкой на фрейм
- «Возьми цвета и отступы из макета, не придумывай свои»
- «Используй компоненты из нашей библиотеки»
- «Сравни, что получилось, с макетом и перечисли расхождения»

Подключается один раз, в настройках агента.

## Подключить в Claude

В приложении Claude или на claude.ai:

1. **Customize** → **Connectors**
2. Найди в списке **Figma** — через поиск или фильтр **Popular for** → **Design**
3. Нажми **Connect** и подтверди вход в Figma

Когда подключение готово, напротив Figma в списке появится галочка.

Если в списке её вдруг нет, добавь вручную: **Add** → **Add custom connector**, адрес сервера — `https://mcp.figma.com/mcp`.

## Подключить в Codex

Здесь ничего вписывать не нужно — Figma есть в списке готовых плагинов:

1. В левой панели открой **Плагины**
2. Найди **Figma** — через поиск или в списке рекомендуемых
3. Нажми **Установить**
4. На странице плагина, в блоке **Приложения**, подключи Figma и подтверди вход

Когда подключение готово, в блоке «Приложения» будет статус **Подключено**.

Вместе с плагином приезжают его навыки — это те же [скиллы](#skills), только уже написанные за тебя: работа с Code Connect, сборка экрана в Figma, перенос макета в код. Лишние можно выключить переключателем.

> Под рабочим VPN подтверждение входа может не пройти: браузер откроется, а авторизация не завершится. Это не поломка настроек — запрос просто не доходит. Подключись с компьютера, где есть нормальный доступ и к Figma, и к самому агенту: дальше подключение сохранится.

## Если работаешь в терминале

Claude Code — одна команда, потом `/mcp` в сессии для входа:

```
claude mcp add --transport http figma https://mcp.figma.com/mcp
```

Codex — две строки в `~/.codex/config.toml` и вход командой `codex mcp login figma`:

```toml
[mcp_servers.figma]
url = "https://mcp.figma.com/mcp"
```

## Как дать агенту нужный макет

Агент не угадает, какой именно фрейм тебе нужен, — дай ссылку. В Figma выдели фрейм, нажми правой кнопкой и выбери **Copy link to selection**. Вставь ссылку в промт:

```
Собери этот экран по макету: <ссылка>. Цвета, размеры и отступы бери из макета. Данные подставь вымышленные.
```

> Макет кейса «Выпуск новой карты» из практики — [ссылка](https://www.figma.com/design/2UQNBYDCGL5UrNXp1JbTJX/Воркшопы?node-id=44-4732). Открой его сам, прежде чем давать агенту фреймы: увидишь, что именно предстоит собрать.

## Что стоит знать заранее

Удалённый сервер `mcp.figma.com` работает на всех тарифах Figma. Есть ещё локальный вариант — через десктопное приложение Figma, но он требует платного тарифа с Dev или Full seat.

Агент видит те файлы, к которым есть доступ у твоей учётной записи Figma. Отдельно раздавать права не нужно, но и лишнего он не увидит.

> Подключая Figma к внешнему агенту, ты открываешь ему содержимое макетов. Для учебных демок и собственных файлов это нормально. Рабочие макеты банка — по правилам компании: смотри [Что лучше не делать](#rules), там же про Nessy.
