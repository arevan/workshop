---
title: Шаблон промта
slug: prompts
---

Магического идеального промта не существует. Работает не одна гениальная формулировка, а хороший цикл коротких итераций: попросил → Run → проверил → попросил следующее.

Но у хорошего промта есть структура. Она нужна, чтобы агент не додумывал за тебя то, чего ты не сказал.

## Структура

```
Контекст — что собираем
Задача — что изменить сейчас
Поведение — что делает пользователь → что происходит
Ограничения — что не менять
Готово, когда… — как проверить результат
```

Не обязательно писать все пять пунктов каждый раз. Но два из них новички пропускают чаще всего, и именно из-за них всё ломается:

**Ограничения.** Без них агент «заодно» перепишет соседний экран, поменяет цвета и отрефакторит то, что работало.

**Готово, когда…** Без этого агент не знает, где остановиться, и либо делает половину, либо уходит в лишнее.

## Плохо и хорошо

Плохо: «Сделай красивый экран оплаты». Непонятно, что происходит при нажатии, что считать красивым и где конец задачи.

Хорошо: «По тапу на карточку открой sheet с деталями. Остальной экран не меняй. После подтверждения закрой sheet и переведи карточку в состояние „Оплачено“».

## Готовые примеры

Открыть sheet по тапу:

```
По тапу на карточку товара открывается sheet с деталями:
изображение, название, цена, кнопка «Добавить».
Sheet закрывается свайпом вниз и кнопкой закрытия.
Остальные экраны не трогай.
Готово, когда sheet открывается и закрывается без визуальных скачков.
```

Добавить состояние:

```
Добавь у кнопки «Оплатить» три состояния: обычное, загрузка (2 секунды,
спиннер вместо текста) и успех (галочка, кнопка неактивна).
Логику оплаты не пиши — просто таймер.
Готово, когда состояния сменяются по тапу и не залипают.
```

Анимация:

```
Сделай переход между списком и деталями плавным: карточка
разворачивается в экран деталей, 0.35 секунды, с пружиной.
Содержимое экранов не меняй.
Готово, когда переход идёт в обе стороны и не мигает.
```

Haptic:

```
Добавь haptic feedback: лёгкий при выборе элемента списка,
успешный при подтверждении действия.
Больше ничего не меняй.
Готово, когда на телефоне отдача чувствуется в обоих случаях.
```

Исправить ошибку, не задев остальное:

```
При запуске приложение падает с этой ошибкой:

<вставь текст ошибки целиком>

Исправь только причину падения. Не рефактори другие файлы,
не меняй вёрстку экранов. Объясни в одном предложении, что было не так.
```

Урезать задачу, если дважды не вышло:

```
Откатись к прошлому коммиту. Давай сделаем то же самое, но проще:
сначала только открытие sheet по тапу, без анимации и без состояний.
```

## Ещё пара приёмов

Проси агента показать варианты, если сам не уверен: «предложи три способа показать это состояние, коротко». Выбирать проще, чем формулировать с нуля.

Если результат не тот, не объясняй заново всю задачу — скажи, что именно не так: «слишком быстро», «карточка дёргается в конце», «не туда сдвигается». Точная правка одной детали работает лучше переписанного промта.
